<p class="ot-eyebrow">What is OpenTunnel?</p>

## Great agents, stuck on one machine.<br />Let's fix that.

<p class="ot-lede">Agents are brilliant on the machine they run on. The moment the task lives on another machine, they hit a wall of key distribution, firewall rules, and standing credentials. Permanent infrastructure for a temporary need.</p>

<p class="ot-support">OpenTunnel is an ephemeral, end-to-end encrypted command tunnel built for exactly this moment. You start one foreground process on the remote machine and paste the printed prompt into your agent. From then on, the agent runs commands there like any other tool call: it sends a command, and stdout, stderr, and the real exit code come back as if the machine were local.</p>

<p class="ot-support">There is nothing to install and nothing to provision. No keys to create and distribute, no inbound ports to open, no account to register. The two machines talk WireGuard to each other, and a public relay on the path forwards ciphertext it cannot read. When the task is done, you press Ctrl+C: the session ends, the keys are removed, and the address stops working forever.</p>

<p class="ot-eyebrow">How it works</p>

## Three steps, zero infrastructure

</div>

<Steps>

1. **Start a session on the remote machine.**

   ```bash
   curl -fsSL https://beta.opentunnel.sh | sh
   ```

   A temporary binary is downloaded, verified against the checksum pinned in the script, and one foreground session starts.

2. **Paste the generated prompt into your agent.**

   The agent runs a one-line installer, which claims the tunnel and pins it to that machine. From then on it runs commands there and gets stdout, stderr, and exit codes back as if they were local tool calls.

3. **Press Ctrl+C when you're done.**

   The session ends, both temp directories are removed, and the address stops working. Nothing persists on either machine.

</Steps>

</ContainerSection>

<p class="ot-eyebrow">Security</p>

## The address stops working the moment your agent connects.

<p class="ot-lede">The tunnel address ends up in your agent's context and its provider's logs. So it is only a key until your agent claims the tunnel, and worthless afterwards.</p>

</div>

<p class="ot-eyebrow">Philosophy</p>

## Deliberately small

<p class="ot-lede">OpenTunnel keeps the access model temporary and narrow on purpose. That is the security model, not a missing feature list. No accounts, no daemons, no persistent state, one pinned client per tunnel.</p>
