OpenTunnel gives your AI agent the ability to run commands on a remote machine as if they were local tool calls. This page takes you from nothing to a working tunnel in about a minute. No installation, no account, no configuration.

<Aside type="note" title="Beta">
v2 is published at `https://beta.opentunnel.sh`. The apex domain keeps serving the first version until v2 is generally available.
</Aside>

## Your first tunnel

<Steps>

1. **Start a session on the machine your agent should reach.**

   On the remote machine run:

   ```bash
   curl -fsSL https://beta.opentunnel.sh | sh
   ```

   This downloads a small binary, verifies it against the checksum pinned in the script, and opens one foreground session. The process prints a ready-made prompt for your agent and keeps running. As long as it runs, the tunnel is open; the moment it stops, access is gone.

   The script is plain text. Curl it without the pipe first if you want to read what runs.

2. **Paste the printed prompt into your agent.**

   The session prints something like:

   ```text
   I opened an OpenTunnel session for you: temporary command access to a
   remote machine through an encrypted tunnel.

   Setup (run once, on this machine):

       curl -fsSL https://beta.opentunnel.sh/agent | sh -s -- tc...

   The installer prints the path of a `remote` helper, e.g.
   /tmp/opentunnel-agent.XXXXXX/remote. Use it for every remote command:

       <path>/remote 'uname -a && pwd'
   ```

   Hand that to your agent: [OpenCode](https://opencode.ai), or anything that can run shell commands. The agent runs the installer once, then uses the `remote` helper for everything. It receives stdout, stderr, and the real exit code, exactly as if the command had run locally.

3. **Let the agent work.**

   From here you talk to your agent as usual. For example:

   > Install a Minecraft Crossplay server.

   Commands run without per-command approval for as long as your foreground session is running, and several may run at the same time.

4. **Press Ctrl+C when you're done.**

   The session ends, both temp directories are removed, and the tunnel address stops working forever. There is nothing to clean up and nothing left behind.

</Steps>

<Aside type="caution" title="The address is a bearer secret until your agent claims it">
Anyone holding a fresh tunnel address can claim it during the first five minutes. Once your agent has claimed it, the tunnel is pinned to that one machine's key and the address alone is useless. Don't paste addresses into shared logs, tickets, or long-lived notes.
</Aside>

## Moving files

The agent installer writes two things next to each other: the `remote` helper and an `ssh` wrapper for the standard tools.

```bash
remote --put ./patch.diff /tmp/patch.diff
remote --get /var/log/build.log ./build.log

rsync -av -e /tmp/opentunnel-agent.XXXXXX/ssh ./dist opentunnel:/srv/app
scp -O -S /tmp/opentunnel-agent.XXXXXX/ssh ./file opentunnel:/srv/app/
```

## Good to know

- Commands must be **non-interactive**: there is no PTY and no stdin from a terminal. Avoid `sudo` unless it is passwordless.
- **One agent per tunnel.** The first client to claim the tunnel is pinned to it; a second machine cannot join. This is part of the [security model](/concepts/security-model/), not a limitation to engineer around.
- Commands run in a **login shell** in the session working directory, so your `.profile` environment is available. Anything that profile prints goes into the command output too.
- The session ends by itself after 30 minutes without a command. Set `OPENTUNNEL_TTL` if you also want a hard limit on the total, and `OPENTUNNEL_CWD` to choose the working directory. The full list is in the [CLI reference](/reference/cli/).
- The agent machine needs an `ssh` client. Both machines need Linux or macOS on amd64 or arm64.
